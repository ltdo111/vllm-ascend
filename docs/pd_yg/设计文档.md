# DeepSeek-V4-Flash 异构 1P1D PD 分离设计文档

## 1. 背景和目标

本设计面向 DeepSeek-V4-Flash 的异构硬件 PD 分离推理服务：

- Prefill 使用 Atlas 800 A2 或 Atlas 800 A3。
- Decode 使用 A5 / Ascend 950DT。
- 优先验证 A2 Prefill -> A5 Decode，再验证 A3 Prefill -> A5 Decode。
- A2 机器规格：8 卡，单卡 64GB。
- A5 机器规格：8 卡，单卡 96GB。

模型权重约束：

- A2/A3 Prefill 使用 `DeepSeek-V4-Flash-w8a8-mtp` 量化权重。
  - ModelScope: `Eco-Tech/DeepSeek-V4-Flash-w8a8-mtp`
- A5 Decode 使用 DeepSeek 官方原始 `DeepSeek-V4-Flash` 权重。
  - Hugging Face: `deepseek-ai/DeepSeek-V4-Flash`
  - Attention 权重为 MXFP8。
  - MoE 权重为 MXFP4，4-bit weight + 8-bit activation 计算，即 W4A8。
  - 不需要额外 Ascend 专用量化或权重转换。

当前脚本位置：

- Prefill A2: `docs/pd_yg/run/prefill/a2_run_dp_template.sh`
- Prefill A3: `docs/pd_yg/run/prefill/a3_run_dp_template.sh`
- Decode A5: `docs/pd_yg/run/decode/a5_run_dp_template.sh`

## 2. 当前结论

### 2.1 Connector 选择

DeepSeek-V4-Flash 场景建议首版使用 `MooncakeHybridConnector`，不使用上一版计划中的 `MooncakeConnectorV1` 作为主方案。

原因：

- 现有 A2/A3 Prefill 脚本已经使用 `MooncakeHybridConnector`。
- DeepSeek-V4-Flash 涉及 hybrid KV cache、MTP、MXFP8/W4A8 等路径。
- PPT 中也提到 `MooncakeHybridConnector` 面向 DeepSeek V4 类 hybrid attention 场景。

### 2.2 1P1D 定义

本设计中的 1P1D 定义为：

- 1 个 Prefill 节点或实例组。
- 1 个 Decode 节点或实例组。

当前脚本实际拓扑是：

- Prefill: `DP=8, TP=1`
- Decode: `DP=4, TP=1`

因此这里不是单进程 `DP=1`，而是 1 个 P 集群组 + 1 个 D 集群组。

### 2.3 首版边界

首版只做以下能力：

- A2 Prefill -> A5 Decode 跑通。
- A3 Prefill -> A5 Decode 回归验证。
- 使用 `MooncakeHybridConnector`。
- P/D 允许权重不同，但必须校验 KV cache 规格兼容。
- 暂不引入 Pool 模式。
- 暂不支持 P/D KV dtype 或 KV layout 自动转换。

### 3.6 Mooncake TransferEngine 协议配置

文件：

- `vllm_ascend/distributed/kv_transfer/utils/mooncake_transfer_engine.py`

函数：

- `GlobalTE.get_transfer_engine`

现状：

```python
self.transfer_engine.initialize(hostname, "P2PHANDSHAKE", "ascend", device_name)
```

修改内容：

- 增加 `protocol` 参数。
- 默认值保持 `"ascend"`，兼容现有行为。
- 记录首次初始化配置。
- 如果后续重复调用但协议或 device 不一致，直接报错。

修改原因：

- 当前协议硬编码，无法显式支持 A2/A3 -> A5 的异构部署。
- P/D 多进程场景中 TransferEngine 重复初始化时，如果配置不一致，应快速失败。

建议代码草案：

```python
class GlobalTE:

    def __init__(self):
        self.transfer_engine: MooncakeTransferEngine | None = None
        self._init_config: tuple[str, str, str | None] | None = None

    def get_transfer_engine(
        self,
        hostname: str,
        device_name: str | None,
        protocol: str = "ascend",
    ) -> MooncakeTransferEngine:
        init_config = (hostname, protocol, device_name)

        if self.transfer_engine is None:
            self.transfer_engine = MooncakeTransferEngine()
            ret_value = self.transfer_engine.initialize(
                hostname,
                "P2PHANDSHAKE",
                protocol,
                device_name,
            )
            if ret_value != 0:
                raise RuntimeError(
                    "Mooncake Transfer Engine initialization failed. "
                    f"hostname={hostname}, protocol={protocol}, "
                    f"device_name={device_name}, ret={ret_value}")
            self._init_config = init_config
        elif self._init_config != init_config:
            raise RuntimeError(
                "Mooncake Transfer Engine has already been initialized with "
                f"{self._init_config}, but got {init_config}.")

        return self.transfer_engine
```

def _validate_remote_metadata(self, remote_metadata: MooncakeAgentMetadata):
    if remote_metadata.block_size != self.block_size:
        raise ValueError(
            "Incompatible KV block size between prefill and decode. "
            f"local={self.block_size}, remote={remote_metadata.block_size}.")

    if len(remote_metadata.block_lens) != len(self.kv_caches):

            f"local={len(self.kv_caches)}, "

### 3.11 量化路径约束

文件：

- `vllm_ascend/quantization/methods/w8a8_pdmix.py`
- `vllm_ascend/quantization/methods/w4a8.py`
- `vllm_ascend/quantization/methods/w4a8_mxfp4.py`
- `vllm_ascend/quantization/fp8_config.py`

修改内容：

- 首版不做 P/D 权重转换。
- 不要求 P/D 使用相同权重文件。
- 增加设计约束和必要检查：
  - Prefill W8A8-MTP 只负责产生 KV。
  - Decode 原始 DeepSeek-V4-Flash 负责消费 KV 并生成 token。
  - 两侧 KV cache dtype/layout/block size 必须一致或明确兼容。
  - 如不一致，首版直接启动失败，不做自动转换。

修改原因：

- 用户明确指出 A2/A3 和 A5 使用权重不一致。
- 不能用模型路径一致性作为 PD 兼容条件。
- 需要防止 W8A8 PDMix、W4A8/MXFP4、FP8 配置之间出现隐式错误路径。

## 8. A3 Prefill 与 A5 Decode 的 KV dtype/layout 兼容性分析

### 8.1 输入配置

本次基于以下两个模型目录的 `config.json` 分析：

- A5 Decode: `/mnt/weight/DeepSeek-V4-Flash`
- A3 Prefill: `/mnt/weight/DeepSeek-V4-Flash-w8a8-mtp`

两份 `config.json` 的关键模型结构字段一致：

```text
architectures = ["DeepseekV4ForCausalLM"]
model_type = deepseek_v4
torch_dtype = bfloat16
num_hidden_layers = 43
num_nextn_predict_layers = 1
hidden_size = 4096
num_attention_heads = 64
num_key_value_heads = 1
head_dim = 512
index_head_dim = 128
index_n_heads = 64
q_lora_rank = 1024
qk_rope_head_dim = 64
sliding_window = 128
max_position_embeddings = 1048576
compress_ratios = [0, 0, 4, 128, ..., 4, 0]
```

因此从模型结构看，A3 Prefill 与 A5 Decode 是同一个 DeepSeek V4 Flash 架构。

### 8.2 启动参数约束

A3 Prefill 当前脚本使用：

```bash
--block-size 128
--quantization ascend
--tokenizer-mode deepseek_v4
--speculative-config '{"num_speculative_tokens": 1, "method": "mtp","enforce_eager": true}'
--kv-transfer-config '{"kv_connector": "MooncakeHybridConnector", "kv_role": "kv_producer", ...}'
```

A5 Decode 必须保持以下参数与 Prefill 对齐：

```bash
--block-size 128
--tokenizer-mode deepseek_v4
--speculative-config '{"num_speculative_tokens": 1, "method": "mtp", "enforce_eager": true}'
--kv-transfer-config '{"kv_connector": "MooncakeHybridConnector", "kv_role": "kv_consumer", ...}'
```

### 8.3 代码推导出的 KV cache 差异

虽然两份 `config.json` 一致，但当前代码会根据设备类型生成不同的 DeepSeek V4 KV cache spec。

非 A5，即 A2/A3 路径：

```text
DSV4_BLOCK_SIZES[128] = [[128, 128, 8, 32], [16640, 131072]]
MLA KV dtype = kv_cache_dtype_str_to_dtype(cache_dtype, model_config)，默认倾向 bfloat16
MLA head_size = 512
Indexer K dtype = int8
Indexer scale dtype = float16
SWA head_size = 512
```

A5 路径：

```text
DSV4_BLOCK_SIZES_A5[128] = [[128, 128, 8, 16], [16896, 81920]]
MLA KV dtype = float8_e4m3fn
cache_config.cache_dtype = "float8_e4m3fn"
MLA head_size = 512 + 128 = 640
Indexer K dtype = float8_e4m3fn
Indexer scale dtype = float32
SWA head_size = 640
```

结论：

| 项 | A3 Prefill | A5 Decode | 判断 |
|---|---|---|---|
| `model_type` | `deepseek_v4` | `deepseek_v4` | 兼容 |
| 层数/head/compress ratio | 一致 | 一致 | 兼容 |
| `block-size` | 128 | 128 | 可兼容 |
| MLA KV dtype | 默认倾向 BF16 | `float8_e4m3fn` | 不兼容 |
| MLA KV head_size | 512 | 640 | 不兼容 |
| Indexer K dtype | `int8` | `float8_e4m3fn` | 不兼容 |
| scale dtype | `float16` | `float32` | 不兼容 |
| DSV4 block sizes | `[128,128,8,32]` | `[128,128,8,16]` | 不完全兼容 |
| padded page size | `[16640,131072]` | `[16896,81920]` | 不兼容 |

因此，`config.json` 一致不代表 KV cache dtype/layout 一致。当前 A3 Prefill 生成的 KV cache 不能直接作为 A5 Decode 的原始 KV bytes 消费。

### 8.4 首版代码落地策略

首版不做隐式 KV dtype/layout 转换，先实现 fail-fast 校验：

- `MooncakeHybridConnector` 在注册 KV cache 后，基于实际 tensor 生成 `kv_cache_signature`。
- signature 包含：
  - dtype
  - 单 block shape
  - stride
  - element size
  - block length
  - block stride
  - hybrid group index
- Producer 在 handshake metadata 中携带 signature。
- Consumer 首次获取远端 metadata 时，与本地实际 signature 比对。
- 不一致时直接报错，避免 A5 将 A3 的 KV bytes 按错误 layout 解释。

已落地代码项：

- `vllm_ascend/distributed/kv_transfer/kv_p2p/mooncake_hybrid_connector.py`
  - 增加 `kv_cache_signature` metadata。
  - 增加实际 KV tensor signature 构造。
  - Decode 侧获取远端 metadata 后执行 dtype/layout/block length 校验。
  - 解析 `protocol`、`device_name`、`heterogeneous_pd`、P/D DP/TP 配置。
  - 对缺失 P/D 拓扑、`prefill_tp_size < decode_tp_size`、`prefill_tp_size % decode_tp_size != 0` 做启动期报错。
- `vllm_ascend/distributed/kv_transfer/utils/mooncake_transfer_engine.py`
  - `GlobalTE.get_transfer_engine` 支持 `protocol` 和 `device_name`。
  - 防止同一进程内以不同 hostname/protocol/device_name 重复初始化 TransferEngine。
- `vllm_ascend/utils.py`
  - `uses_mooncake_connector` 覆盖 `MooncakeHybridConnector` 和 `MooncakeLayerwiseConnector`。
- `docs/pd_yg/run/`
  - 补齐 A5 Decode 模板、Prefill/Decode DP 启动 wrapper 和 proxy wrapper。
  - A2/A3 Prefill 模板改为默认加载 `/mnt/weight/DeepSeek-V4-Flash-w8a8-mtp`。
  - A5 Decode 模板默认加载 `/mnt/weight/DeepSeek-V4-Flash`。

后续如需真正跑通 A3/A2 -> A5，需要在以下方案中二选一：

- 让 A3/A2 Prefill 支持 A5-compatible DeepSeek V4 KV cache layout。
- 在 P -> D 传输链路中实现 DeepSeek V4 A3/A2-to-A5 KV layout 转换。

## 9. 异构传输开关与转换方案

本次代码选择第一种方案：在显式打开异构传输开关时，让 A2/A3 Prefill 端直接生成 A5-compatible DeepSeek V4 KV cache layout。

选择原因：

- Mooncake 传输链路传输的是 raw bytes。Prefill 端直接生成 Decode A5 可消费的 KV layout 后，P/D 之间仍保持零拷贝/直接 RDMA byte transfer。
- 如果在 P -> D 传输过程中做 dtype/layout 转换，每次请求都需要额外读源 KV、重排、量化、写目标 KV，会增加 TTFT 关键路径开销。
- Prefill 端原生写 A5-compatible KV 的方式，把转换合入已有 KV 写入/量化算子路径，理论性能高于传输中转换。

新增显式配置：

```json
{
  "kv_connector_extra_config": {
    "heterogeneous_pd": true,
    "enable_heterogeneous_transfer": true,
    "prefill": {
      "device_type": "A2",
      "dp_size": 8,
      "tp_size": 1
    },
    "decode": {
      "device_type": "A5",
      "dp_size": 4,
      "tp_size": 1
    }
  }
}
```

代码行为：

- `use_a5_kv_cache_layout()` 判断当前实例是否应使用 A5-compatible KV cache layout。
- 真实 A5 Decode 永远使用 A5 KV layout。
- 非 A5 Prefill 只有在 `kv_role=kv_producer`、`enable_heterogeneous_transfer=true` 且 `decode.device_type=A5` 时使用 A5-compatible KV layout。
- `MooncakeHybridConnector` 解析并校验该开关，目前只允许 Prefill A2/A3 -> Decode A5。
- DeepSeek V4 KV spec、DSV4 block sizes、SWA/Indexer cache dtype、DSA metadata slot mapping、KV scatter/indexer quant helper 按该判断选择 A5-compatible 路径。
- KV cache signature 校验仍保留；如果实际 tensor dtype/layout/block stride 仍不一致，Decode 侧会继续 fail fast。

涉及代码文件：

- `vllm_ascend/utils.py`
  - 新增 `use_a5_kv_cache_layout()`。
  - 新增 `_normalize_ascend_device_type()`。
- `vllm_ascend/models/layer/attention/layer.py`
  - `get_dsv4_block_sizes()` 支持按 `vllm_config` 选择 A5 DSV4 block size。
  - `DSAAttention.get_kv_cache_spec()` 在异构开关下生成 A5-compatible MLA KV spec。
- `vllm_ascend/models/deepseek_v4.py`
  - `AscendDeepseekV4IndexerCache.get_kv_cache_spec()`、`AscendDeepseekV4SWACache.get_kv_cache_spec()`、`Indexer`、`DeepseekV4Attention` 接入 A5-compatible KV layout 判断。
- `vllm_ascend/ops/dsa.py`
  - `_build_kv_cache()` 在异构开关下构造 A5 的 7 元 KV cache tuple。
- `vllm_ascend/attention/dsa_v1.py`
  - `AscendDSAMetadataBuilder` 和 `AscendDSAImpl` 增加 `_dsa_kv_ops`，使 slot mapping、metadata op、KV scatter、indexer quant/cache 解包按目标 A5 layout 选择。
